### Correção de bug no arquivo de config
- `~/Documentos/DevOps/conf/conky/conky.conf` continha um wrapper `sudo cat > /etc/conky/conky.conf <<EOF ... EOF` para "auto-instalar" a config
- **Bug 1:** arquivo com terminações de linha CRLF (`\r\n`) — o `EOF` final virava `EOF\r`, o heredoc bash nunca fechava
- **Bug 2 (causa raiz):** mesmo corrigido o CRLF, o heredoc ainda falhava ao ser executado via `sudo bash arquivo.conf` no ambiente não-interativo — o conteúdo da config era interpretado linha a linha como comandos shell (`${color orange}` → erro "bad substitution" / "substituição incorreta")
- **Decisão:** abandonar o padrão heredoc auto-instalável; o arquivo agora é uma config Lua pura do Conky (sem wrapper), instalada via `sudo cp` direto

## 🔍 Descobertas técnicas

- `lscpu` está em locale pt-BR (`Nome do modelo:`), então `/proc/cpuinfo` (sempre em inglês, `model name`) é a fonte estável para automação
- `lspci` só reporta o nome do chip GPU (ex.: "Polaris 20 XL [Radeon RX 580 2048SP]"), nunca o fabricante da placa (AIB partner, ex. Sapphire/ASUS) — essa informação não existe no PCI ID
- `glxinfo | grep "OpenGL renderer"` dá o nome de GPU mais limpo e amigável que `lspci`
- `/sys/devices/virtual/dmi/id/board_vendor` e `board_name` são legíveis por usuário comum; `dmidecode` exige root e falha silenciosamente sem sudo (`Permission denied` em `/sys/firmware/dmi/tables/smbios_entry_point`)
- Sudo interativo (pedir senha) não funciona em comandos disparados pelo assistente — sempre pedir ao usuário para rodar via `! <comando>` no terminal dele
- `killall conky` pode deixar processos órfãos vivos; conferir sempre com `pgrep -fa conky` após reiniciar
- `sensors` (lm-sensors) pode reportar erros de I/O em subfeatures não suportadas por drivers específicos de placa (ex.: `gigabyte_wmi`) sem que os dados relevantes sejam afetados — normal suprimir com `2>/dev/null`
- Pacote `mcp-obsidian` (PyPI, até v0.2.2) não suporta porta/host customizados via env var — hardcoded para `127.0.0.1:27124`
