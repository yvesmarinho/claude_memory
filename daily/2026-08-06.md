### gfy-runner — correção de bug
- **Bug:** subcomando `update` não aceita `--backend` e `--model` → erro `unknown update option: --backend`
- **Fix:** filtro adicionado em `run_graphify()` — remove flags extract-only (`--backend`, `--model`, `--code-only`) quando subcomando é `update`
- Validado com 4 casos de teste: update com backend/model (removidos), extract (intocado), update com --force --no-cluster (mantidos), update com --code-only (removido)

### Análise graphify — wifi-qrcode-generator
- 3 execuções analisadas e comparadas
- **Diagnóstico:** fase LLM de enriquecimento de nós não rodou em nenhuma execução (`ast_hash == semantic_hash`)
- `.graphifyignore` corrigido: V01.py, V02.py, `_index.md` excluídos → grafo reduziu de 8 para 3 nós
- Causa raiz: projeto muito simples (1 arquivo, 1 função) — graphify não aciona LLM semântico abaixo de um limiar de complexidade
- **Conclusão:** projeto-piloto inadequado; usar `cmdb-platform` ou `mnemosine` para validação real do pipeline LLM

## 🔍 Descobertas técnicas

- `graphify update` não suporta `--backend`, `--model`, `--code-only` — apenas `--force` e `--no-cluster`
- `ast_hash == semantic_hash` no manifest → prova de que fase LLM não rodou
- Tokens LLM consumidos (842 input, 124 output) foram usados para clustering, não enriquecimento de nós
- O vault `claude_memory` não estava montado no sandbox do Cowork — nota criada em outputs para cópia manual
