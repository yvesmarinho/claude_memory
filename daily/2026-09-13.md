# 2026-09-13

## 🎯 Sessão — buzzclubhub: recuperação de contexto e how-to de deploy no Vercel (homologação)

### ✅ Concluído

**Recuperação de contexto**: consultado o vault para retomar a sessão anterior
(2026-09-12) — PR #16 (`develop → main` no upstream) ainda aguardando review da
Audrey; secrets `VITE_SUPABASE_URL`/chave ainda faltando no CI do upstream.

**Discussão — hospedagem sem Lovable**: usuário perguntou se é possível hospedar
a aplicação no GitHub sem depender do Lovable. Confirmado que sim — o projeto é
um SPA Vite+React puro (`npm run build` gera `dist/` estático), Lovable é só
origem do scaffold. Apresentadas duas opções: GitHub Pages (bloqueado hoje por
ser fork privado — Pages em repo privado exige plano pago) e Vercel/Netlify
conectado ao GitHub.

**How-to Vercel criado**: usuário optou por Vercel, objetivo declarado é
**homologação de atualizações** (não produção). Criado
`docs/guides/DEPLOY_VERCEL_HOMOLOGACAO.md` no repo do projeto, cobrindo:
- Import do repo `yvesmarinho/buzzclubhub` (fork privado) no Vercel.
- Build settings (`npm run build`, output `dist`, install com
  `--allow-remote=all` — necessário pelo tarball CDN do `xlsx`).
- Variáveis `VITE_SUPABASE_*` — alerta explícito para não reutilizar o
  Supabase de produção da Audrey em homologação sem projeto Supabase dedicado.
- Estratégia de branch: Production Branch do Vercel = `001-refatoracao-hardening`
  (branch de trabalho atual), com Preview Deployments automáticos por PR.
- SPA routing (fallback nativo do preset Vite no Vercel, `vercel.json` só se
  necessário).
- Passos de validação pós-deploy (login, portal do cliente, CORS/Supabase).

Documento não cobre: domínio custom, migrations/seed de homologação, nem
substitui os quality gates do CI (lint/typecheck/test seguem via GitHub
Actions).
