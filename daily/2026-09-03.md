**Ambiente Supabase local via Docker** — `npx supabase start` bateu no drift já documentado numa sessão anterior (`docs/bugs/2026-09-03-migrations-drift-local-bootstrap.md`, tabela `client_onboarding` nunca criada por migration). Criada fixture local-only (`supabase/migrations/20260713170615_local-fixture-client-onboarding.sql`) que destrava o replay completo das 105 migrations — schema aproximado via `types.ts`, RLS restritiva por padrão, **não** fiel ao schema real.

**T053 retomada e essencialmente fechada nos hooks** — infra de teste reutilizável criada (`src/test/mockSupabase.ts`: mock chainável/"thenable" do client Supabase incluindo `.channel`, `.rpc`, `.storage.from`, `.auth.getUser`; `mockAuth.ts`; `renderHookWithProviders.tsx`), e escritos testes para **todos os 60 hooks** de `src/hooks/` (0 → 628 testes), em 4 tiers de prioridade (RBAC → financeiro → portal do cliente → CRUD geral), com checkpoints de lint + `tsc --noEmit` + suíte completa a cada tier.

### ⚠️ Aprendizados / gotchas

- **`.env` local quebra `security-regressions.test.ts`**: os testes de segurança chamam Edge Functions reais via `VITE_SUPABASE_URL` — como Edge Functions não rodam no Docker local, um teste (`client-portal-auth create-user`) passa a falhar com 500 em vez de 401/403. Não é regressão real, é efeito do ambiente. Suíte completa só é confiável contra produção (mesmo padrão do CI) — resolvido trocando `.env` temporariamente a cada checkpoint de cobertura, sempre restaurado ao local em seguida (backup de produção em `.secrets/env-production-backup.txt`, fora do git).
- Mock naïve do Supabase (um resultado configurado por tabela) não distingue duas queries sequenciais à mesma tabela dentro do mesmo mutationFn — precisou simplificar um teste (`useOKRs` — recálculo de progresso do objetivo) em vez de forçar uma branch específica.
- Vazamento local: apareceu um arquivo `.env copy` não rastreado e **não coberto pelo `.gitignore`** (só `.env` exato está ignorado) — sinalizado ao usuário no fim da sessão, não deletado nem commitado.
- Padrão de mock estabelecido (chainable + thenable, resolve independente de onde o `await` acontece) generaliza bem para qualquer hook Supabase novo — reutilizável em sessões futuras do projeto.
